# Cognivex CDDA Web 介面使用指南

## 🚀 快速開始

### 方法 1: 使用啟動腳本（Windows）
```bash
run_cdda_app.bat
```

### 方法 2: 命令列啟動
```bash
streamlit run app_cdda.py
```

### 方法 3: 指定埠號
```bash
streamlit run app_cdda.py --server.port 8502
```

啟動後，瀏覽器會自動開啟 `http://localhost:8501`

## 🎮 使用流程

### 步驟 1: 選擇分析框架
在側邊欄選擇：
- **CDDA Framework (推薦)** - 自主診斷代理
- **傳統 LangGraph** - 標準分析管線

### 步驟 2: 選擇受試者
從下拉選單選擇要分析的受試者（例如：sub_0005）

系統會自動顯示：
- 受試者 ID
- 真實標籤（AD/NC）

### 步驟 3: 配置 CDDA 設定（如使用 CDDA）

#### 啟用 LLM 模式
- ✅ **開啟**: 使用雙 LLM 架構（Agent A + Agent B）
- ❌ **關閉**: 使用規則式降級（更快，不需 GPU）

#### 顯示推理鏈
- ✅ **開啟**: 顯示完整的代理推理過程
- ❌ **關閉**: 只顯示最終報告

### 步驟 4: 開始分析
點擊 **🚀 開始分析** 按鈕

系統會顯示進度：
1. 初始化 CDDA Agent (10%)
2. 執行 CDDA 分析 (30%)
3. 生成診斷報告 (70%)
4. 分析完成 (100%)

### 步驟 5: 查看結果

#### CDDA 結果包含：
1. **診斷摘要**
   - 受試者 ID
   - 預測結果（AD/NC）
   - 信心度
   - 不確定性評分（UQ）
   - 代理決策類型

2. **關鍵發現**
   - 診斷報告文字

3. **反事實分析**（如觸發）
   - 原始預測 vs 模擬後預測
   - 信心度變化
   - 特徵影響解釋

4. **異常區域檢測**（如觸發）
   - 異常腦區列表
   - Z-score 評分

5. **預測驗證**
   - 真實標籤 vs 模型預測
   - 信心度和 UQ 評分

6. **完整推理鏈**（可展開）
   - Agent A 編排過程
   - MCP 操作記錄
   - A2A 交接
   - Agent B 合成過程

7. **詳細元數據**（可展開）
   - 完整的分析元數據 JSON

## 🎯 CDDA 決策邏輯

### 決策 A: 反事實模擬觸發
**條件:** UQ 評分 > 0.8

**行動:**
- 執行反事實模擬
- 識別關鍵驅動特徵
- 量化特徵影響

**報告包含:**
- 原始 vs 模擬預測
- 信心度變化
- 關鍵驅動因素

### 決策 B: 異常調查觸發
**條件:** 檢測到異常腦區（|Z-score| > 2.5）

**行動:**
- 查詢知識圖譜
- 獲取臨床背景
- 評估混合病理

**報告包含:**
- 異常區域列表
- 臨床意義
- 相關疾病

### 決策 C: 標準報告
**條件:** 無高不確定性或異常

**行動:**
- 生成標準診斷報告
- 突出主要特徵

**報告包含:**
- 預測和信心度
- 主要貢獻區域
- 標準建議

## 📊 結果解讀

### 預測結果
- **AD**: 阿茲海默症
- **NC**: 正常對照組

### 信心度
- **> 80%**: 高信心
- **60-80%**: 中等信心
- **< 60%**: 低信心

### UQ 評分（不確定性）
- **< 0.5**: 低不確定性
- **0.5-0.8**: 中等不確定性
- **> 0.8**: 高不確定性（觸發反事實分析）

### Z-score
- **|Z| < 2.5**: 正常範圍
- **|Z| > 2.5**: 異常（觸發知識查詢）

## ⚙️ 進階設定

### LLM 模式 vs 規則式模式

#### LLM 模式（use_llm=True）
**優點：**
- 更豐富的臨床推理
- 自然語言解釋
- 上下文感知

**缺點：**
- 需要 GPU（推薦 12GB+ VRAM）
- 執行時間較長（~2-5 分鐘）
- 需要 Ollama 或 HuggingFace

#### 規則式模式（use_llm=False）
**優點：**
- 快速執行（~10-30 秒）
- 不需要 GPU
- 穩定可靠

**缺點：**
- 報告較模板化
- 解釋較簡單

**建議：**
- 開發/測試：使用規則式模式
- 研究/論文：使用 LLM 模式
- 臨床應用：根據需求選擇

## 🐛 故障排除

### 問題 1: 找不到受試者資料
**錯誤訊息:** "找不到任何受試者資料"

**解決方法:**
```bash
# 檢查資料目錄結構
ls data/MRI_processed/

# 應該看到：
# data/MRI_processed/AD/sub_0001/
# data/MRI_processed/NC/sub_0002/
```

### 問題 2: CDDA Agent 初始化失敗
**錯誤訊息:** "CDDA Agent 初始化失敗"

**解決方法:**
```bash
# 檢查模型檔案
ls model/cnn_rf/rf_model_NC_vs_AD_GM_only.joblib

# 檢查 Neo4j 連接
python -c "from app.core.knowledge.neo4j_dao import Neo4jDAO; dao = Neo4jDAO(); dao.close()"
```

### 問題 3: LLM 模式錯誤
**錯誤訊息:** "LLM provider error"

**解決方法:**
```bash
# 檢查 Ollama 是否運行
curl http://localhost:11434/api/tags

# 如果沒有運行，啟動 Ollama
ollama serve

# 或使用規則式模式（關閉 LLM 模式）
```

### 問題 4: 記憶體不足
**錯誤訊息:** "CUDA out of memory"

**解決方法:**
1. 關閉 LLM 模式
2. 使用 8-bit 量化（預設已啟用）
3. 減少批次大小
4. 關閉其他 GPU 程式

### 問題 5: 分析卡住
**症狀:** 進度條停在某個百分比

**解決方法:**
1. 點擊 **強制停止** 按鈕
2. 檢查終端機錯誤訊息
3. 重新啟動應用
4. 嘗試不同的受試者

## 📈 性能優化

### 快取機制
應用使用 Streamlit 快取來加速：
- CDDA Agent 初始化（只載入一次）
- NIfTI 檔案載入（快取已載入的檔案）

### 建議配置

#### 開發/測試
```python
use_llm = False  # 規則式模式
show_reasoning = False  # 隱藏推理鏈
```
**執行時間:** ~10-30 秒

#### 研究/論文
```python
use_llm = True  # LLM 模式
show_reasoning = True  # 顯示推理鏈
```
**執行時間:** ~2-5 分鐘

#### 臨床應用
```python
use_llm = False  # 規則式模式（快速）
show_reasoning = False  # 簡潔報告
```
**執行時間:** ~10-30 秒
